# U29 `/writing` asks for the shelf only (both runtimes)

Card (MASTER-PLAN 10.6, with 2 "Two runtimes" and 6.2 "Smaller"): an optional
slugs input on `posts.listPublished` in the dev router and both handlers in
`api/index.ts`; `Writing.tsx` passes the shelf's slugs; `api-parity.test.ts`
stays green.

Surface: API procedure, so this needs both runtimes. No schema change, no
route added or moved, no reader-facing copy. Nothing added for a reader to
see, so nothing to retire.

## What changed

- **The input is `{ slugs?, since? }`, not slugs alone.** `/writing` uses the
  listing for two things: reading times on the shelf essays, and the Latest
  group (posts James adds through the admin after the shelf's cutoff, which
  are not on the shelf by slug). Slugs alone would have emptied Latest. So the
  page asks for the live shelf essays by slug *and* anything whose essay date
  (publishedAt, else createdAt, the rule `shelf.ts`, `scripts/lib/shelf.mjs`
  and CLAUDE.md already name) is at or after the cutoff. With either field,
  only those rows come back, in the listing's order. With neither, the full
  listing, exactly as before, so every other caller is untouched.
- `server/posts-listing.ts` (new): the zod input (`slugs`: up to 500 strings;
  `since`: an ISO instant, `z.iso.datetime()`) and `pickListing`.
- `server/routers.ts`: `posts.listPublished` takes that input and applies
  `pickListing` to `listPosts(true)`.
- `api/index.ts`: a self-contained `pickListing` (same rule, no `../server`
  import), applied in both handlers: the single-procedure `trpcHandler` (about
  line 1685) and the batch `processProc` (about line 2590). It is a named
  export so the test can reach it; the handler is still the default export.
  Malformed fields are ignored there (it already parses loosely, and a
  no-input GET can reach it as the whole `{"0":{...}}` object), so a bad
  request gets the full listing, which the page filters anyway. Dev rejects a
  malformed field with zod's BAD_REQUEST. Valid input answers the same in both.
  The filter runs after the DB and static library are merged, so "DB wins on
  slug" is unchanged.
- `client/src/lib/shelf.ts`: `shelfListingInput()` returns the live shelf slugs
  (`liveShelfEssays()`, so a pending essay joins the moment its rewrite lands)
  and the cutoff as an ISO string.
- `client/src/pages/Writing.tsx`: `trpc.posts.listPublished.useQuery(SHELF_LISTING)`
  instead of `useQuery()`. Everything downstream is unchanged: the page still
  applies the shelf rule to whatever comes back.

## What it saves

Measured locally, not on production:
- With the real production function and no database (it serves the static
  essay library), the full listing is 395 KB; the shelf answer is 623 bytes.
  That case shows only one shelf essay, before and after this unit, because
  14 of the 15 live essays exist only in the database.
- With a database-like listing (the static library plus every live shelf
  essay, one post after the cutoff and a retired essay, run through the real
  production `pickListing`), the full answer is 470 KB and the shelf answer
  5.5 KB. Production's full listing is larger still (about 959 database rows
  plus the library).
- The request URL is 732 characters with today's 15 live slugs. With all 58
  shelf essays plus the 7 new ones live it would be about 3 KB, well inside
  URL limits. The production response keeps its `s-maxage=120` CDN cache,
  keyed by URL, so the shelf query has its own cache entry and a shelf change
  gets a new one.

## Review (2026-10-27)

An adversarial review read the diff against the card, reran every gate, and
fixed one problem.

**Fixed: a test that a sibling merge would have broken.** The new `/writing`
test in `essay-shelf.test.tsx` asserted that the request does not carry
`what-christian-nationalism-is-and-is-not`, named as a pending essay. The
pilot landing branch (`land`) adds that essay's rewrite, which makes it
public, so after that merge the request rightly carries it and the test fails.
Git reports no conflict because the two branches touch different lines. I
checked this by merging `land` into a scratch copy: the builder's assertion
failed there ("expected [ …(20) ] to not include
'what-christian-nationalism-is-and-is-…'"). The test now reads every pending
essay from the shelf (`SHELF_ESSAYS` plus `essayVisibility`) and checks that
none of them is asked for. With the fix, `essay-shelf.test.tsx`, `shelf.test.ts`
and `posts-listing.test.ts` all pass on the same merge. Commit 25e2094a.

**Checked and found sound (no change):**
- Both production handlers parse input the way the browser sends it. With no
  input, the single handler sees the whole `{"0":{...}}` object, which has
  neither field, so it returns the full listing. The batch handler sees `null`
  and also returns the full listing. The shelf's input reaches both handlers
  as `{ slugs, since }`.
- The `since` rule matches the client's Latest rule: publishedAt, else
  createdAt, at or after the cutoff. Production rows are Date objects, because
  mysql2 has no `dateStrings`, so the server and the browser see the same
  instants. There is no time-zone gap. The server returns a superset of what
  the page keeps, and the page still applies the shelf rule.
- Order is preserved, so Latest stays newest first. The CDN cache is keyed by
  the full URL, so the shelf query gets its own entry. No other code reads
  `posts.listPublished` from the cache expecting `/writing` to have filled it
  (no `getData` or `setData`). `AdminDeduplicate` invalidates every input.
- `latestCutoff` is pinned by `shelf.test.ts`, so `new Date(LATEST_CUTOFF)`
  at module load cannot throw in a build that passes CI.
- Using `{ slugs, since }` rather than slugs alone is the right departure from
  the card. Without `since`, Latest would empty.
- No sibling in this wave touches `api/index.ts`, `server/routers.ts`,
  `Writing.tsx`, `shelf.ts` or `essay-shelf.test.tsx`.
