# U16 VerseRef and text-only chapter shards

Card (MASTER-PLAN 10.6, with 7.1, 8.2, 9.2): `components/VerseRef.tsx`, a
shard script under `scripts/` and its output in `client/public/bible/text/`,
`Markdown.tsx` (the remark plugin), `ScriptureRef.tsx`, the family, plans,
context-guide, and creed pages that gain live references. Done when John 3:16
in a context guide opens the verse sheet with `ScriptureNote` and then the
Study Bible, an unparseable reference renders as plain text,
`validate-scripture.mjs` passes, and the shard drift check is in CI.

Surface: components, library code, a build script and its generated data, a
CI line. No API procedure, no schema, no route.

## What changed

- **Text-only chapter shards.** `scripts/lib/bible-text.mjs` and
  `scripts/build-bible-text.mjs` write `client/public/bible/text/<book>/<n>.json`
  from `client/public/bible/ch/` as `{ book, chapter, verses: [{ v, t }] }`,
  keeping `later: true` (and the empty text) on the 18 verses the critical
  text omits. 1,189 files, 4.4 MB; John 3 is 4,460 bytes against 41,942.
  `--check` fails when a shard differs from its chapter, is missing, or has
  no chapter behind it; it runs in the CI content-gates step after
  `validate-bible.mjs`. The service worker does not precache them.
- **`lib/bible.ts`**: `fetchChapterText` and `BibleTextChapter`, through the
  module's existing cache (a failed fetch is not cached, so retry works).
- **`lib/verse-text.ts`**: `chaptersOf`, `selectVerses` (the selection
  `passage()` in `scripts/lib/bsb.mjs` makes), `loadPassage` (null past three
  chapters).
- **`lib/scripture-find.ts`**: finds references in running text and hands
  every candidate to U09's `parseScriptureRef`; what it cannot read stays
  text. A short form needs chapter and verse; a capitalized full name may
  stand with a chapter. Ranges, lists, cross-chapter ranges, semicolons, one
  "and" in the same book, numbered books written every way.
- **`components/VerseRef.tsx`**: `VerseRef` and `RefText`. Link mode is a
  wouter `Link` to the chapter at the verse. Sheet mode is a real `<a href>`
  with `aria-haspopup="dialog"`; a plain click opens U14's `Sheet` with the
  verses from the shard, `<ScriptureNote rendering="bsb" />`, and "Open in the
  Study Bible". Loading, failed with retry (`LoadFailed`), too long, and no
  such verse each have their own line. An unreadable reference is plain text.
- **`components/Markdown.tsx` + `components/MarkdownVerseRefs.tsx`**: the
  in-house remark plugin, opt-in through `verseRefs="sheet" | "link"`; text
  inside links, headings, and code is left alone. `lib/prose.tsx` passes
  `verseRefs` through, to Markdown or to `RefText` for plain paragraphs.
- **`components/ScriptureRef.tsx`**: link mode into the Study Bible, not the
  Passage Context tool; a mixed field ("Jonah 3:10 with Jeremiah 18:7-10",
  "Acts 2 (Pentecost ...)") has each reference made live and the note kept.
  Its one caller is `TheologyDoctrine.tsx`.
- **`index.css`**: `.st-verseref` and `.st-passage*`, beside the Sheet rules.
  Tokens only.
- **Pages, by translation** (sheet only where a page quotes the BSB or
  nothing): context guides (prose and key texts, sheet; the ten verse guides
  quote the BSB, the rest quote no verse); creed documents (intro, text,
  notes, sheet; they quote no modern translation); care plans (intro, care
  note, why, practice, reflection, sheet; the plans quote the BSB); family
  reading plans (sheet; nothing quoted); family catechism (link, since the
  verse is printed under it).

One in, one out: no new surface. It retires the Passage Context tool as
`ScriptureRef`'s destination and dead reference text on six page types.

## Review (2026-10-27)

Read the whole diff against the card, sections 2, 7.1, 8.2, and 9.2, and the
siblings' branches. Re-checked the translation claims against the data: the
quotations in the verse guides and the care plans match the BSB shard text
word for word in every case sampled; the creed documents quote no modern
translation (the Augsburg summary's historic wording and one short phrase in
a note are part of the documents). Ran the finder over every reference on the
affected pages (832 found) and over common citation forms; no prose was
taken for a reference.

Fixed:

1. **Every Markdown and Prose page paid for the verse sheet.** `Markdown.tsx`
   and `lib/prose.tsx` imported `VerseRef` statically, so the essay page,
   books, care pages, history and nation essays (about 50 page files) loaded
   the Sheet's Radix chunk (`vendor-ui`, 11.1 KB gzip), the book table and
   parser (3.4 KB), `VerseRef` (2.8 KB), and `ScriptureNote`, about 18 KB
   gzip none of them use. Measured in the build: before the fix the essay
   chunk imported `VerseRef` through `Markdown`; it did not import
   `vendor-ui` before U16. The plugin now lives in `MarkdownVerseRefs.tsx`,
   which `Markdown` loads lazily only when `verseRefs` is set, and `Prose`
   loads `RefText` the same way; until it arrives the text renders as plain
   prose, so nothing waits on it. After the fix, a built `/writing/<slug>`
   and `/help/grief` request none of that code (checked in Chromium).
2. **A merge conflict with U17.** Both branches appended their CSS after
   `.st-stepper__position`; `git merge-tree` of the builder's head with
   U17's branch conflicted in `index.css`. The `.st-verseref` block now sits
   beside the Sheet rules. All five wave branches now merge with U16 without
   conflict (the one remaining conflict in the wave is U13 against U17 in
   `Family.tsx` and `FamilyDevotions.tsx`, not this unit's).
3. **The too-long message named a range for a list.** "Psalms 1; 23; 91;
   139" read "runs from chapter 1 to chapter 139". It now counts: "This
   passage covers 4 chapters. Read it whole in the Study Bible."
4. Tests: the Markdown tests wait for the lazy plugin, a new test pins that
   the text reads whole before the plugin arrives and the same after, and a
   new test covers the chapter count.

Looked at and left:

- A numeral before a reference that makes it invalid hides the reference
  after it ("Day 2 John 3:16" finds nothing; "3 John 5:1" finds nothing).
  Taking "John 3:16" there would also take "John 5:1" from the typo, a link
  to the wrong book; plain text is the safer failure. Nothing in the
  affected data does this.
- Link mode still loads the Sheet's code through `VerseRef` (the catechism
  and doctrine pages, about 14 KB gzip each, after the page paints). When
  U23 turns on link mode for essays it should load the sheet part of
  `VerseRef` on first open, so link-only pages skip `vendor-ui`.
- Key texts on a context guide are about 27 px tall with 8 px between;
  that passes WCAG 2.5.8, not the 44 px the primitives keep.
