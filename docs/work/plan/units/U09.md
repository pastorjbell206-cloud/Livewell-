# U09 One Scripture reference parser

Card (MASTER-PLAN 10.6, 7.1, 9.2): `client/src/lib/scripture-ref.ts` and its
test, `scripts/lib/bsb.mjs`, `lib/bible-notes.ts`, `lib/needs.ts`,
`validate-essays.mjs` (parse check on). Done when "John 3:16," "jn 3 16,"
"1 cor 13," "Romans 13," "Ps 23:1-3," and "Philippians 4:6-7" parse
identically in both, and an unknown book returns null.

Surface: library code and the Study Bible / care pages that link references.
No API procedure, no schema, no route, no reader-facing text added.

## What changed

- `client/src/data/scripture-books.json` (new): the 66 books (code, slug,
  name, testament, chapters, in canon order, the same as
  `client/public/bible/books.json`) and, per book, the abbreviations people
  write (gen, ex, deut, 1 sam, 2 kgs, ps, prov, eccl, song, isa, matt, mt, mk,
  lk, jn, rom, 1 cor, phil, 1 thess, heb, jas, 1 pet, rev, and the rest). It
  is the one alias table; both runtimes read it, the way `shelf.json` serves
  `shelf.ts` and `scripts/lib/shelf.mjs`. Every alias the four old parsers
  knew is in it.
- `client/src/lib/scripture-ref.ts` (new): `parseScriptureRef` (book plus
  spans `{c1, v1, c2, v2}`, v2 Infinity for a whole chapter, or null),
  `findBook`, `bookKey`, `formatRef` ("Psalm 23:1–3", "Romans 7:24–8:1, 5"),
  `refHref(ref, { verse })`, `SCRIPTURE_BOOKS`. Built from `bsb.mjs`'s logic
  and extended: abbreviations; case; periods ("1 Cor. 13"); "1cor"; I/II/III
  and First/Second/Third; loose spacing ("jn 3 16", "jn 3 16-18"); "John
  3.16"; en dashes and other dash characters as hyphens; chapter ranges;
  cross-chapter ranges; verse lists; chapters joined by semicolons ("Romans
  5:1; 8:28"); a lone number in a one-chapter book is a verse ("Jude 3" is
  1:3, "Jude 1" the whole letter). Null for an unknown book, chapter 0 or
  past the book's last chapter, verse 0, a backwards range, or anything left
  over (prose, a trailing period). Verse counts are not checked (the client
  does not have them without the chapter file; `passage()` still throws on
  "John 3:99"). In the build it is its own 9 KB chunk, not in the entry
  bundle, so U15 can load it when the Find field is focused.
- `scripts/lib/bsb.mjs`: `readRef`, the same grammar line for line, returning
  null; `parseRef` now wraps it and still throws (one message: unknown book or
  impossible chapter or verse); `bookKey` exported; the alias table comes from
  the shared JSON instead of `books.json` plus two hand-added names. ROOT is
  now found with `fileURLToPath`, because Vite rewrites
  `new URL("../..", import.meta.url)` and the new client test imports the file
  through Vite (the same pattern `scripts/lib/shelf.mjs` uses).
- `client/src/lib/scripture-ref.test.ts` (new, 12 tests): the card's six read
  the same in both, with the exact spans; unknown books null in both; both
  agree on an 88-item fixture list (spelling, spacing, ranges, lists,
  one-chapter books, and things that are not references); both agree on, and
  read, every reference in the Study Bible's guides, doctrine studies, and
  Find Help pages; `bookKey` agrees; `passage()` still quotes what the parse
  names; the book table equals `books.json`; no alias names two books;
  `formatRef` and `refHref` cases (the old `refHref` and `studyBibleHref`
  tests moved here).
- Retired onto it:
  - `refHref` in `lib/bible-notes.ts` (removed). Callers import it from
    `lib/scripture-ref.ts`: `StudyBibleDoctrines.tsx` (key texts),
    `StudyBibleGuides.tsx` ("Read:" lines; the page no longer fetches
    `books.json`, which it loaded only for this), `study-bible/VerseNotes.tsx`
    (Old Testament behind it, New Testament use, parallels, see also).
  - `studyBibleHref` in `lib/needs.ts` (removed). `help/CarePage.tsx` uses
    `refHref(ref, { verse: false })` for "Read the whole chapter".
  - `refChapters` in `lib/bible-notes.ts` (a fifth parser the plan did not
    list, with its own alias table) now reads the reference a catalogue line
    opens with through `parseScriptureRef`, and adds chapters for each "and"
    that stays in the same book. Its alias table and lookup cache are gone.
  - The `books` argument these needed is gone: `refChapters(ref)`,
    `itemsForPassage(items, slug, chapter?)`, and the `books` prop on
    `VerseEntry`, `VerseByVerse`, and `BookPage` (`StudyBible.tsx`,
    `ChapterNotes.tsx` call sites).
  - `parseRef` in `lib/bible.ts` (OSIS codes, "Jhn.3.16") stays, as the plan
    says, for the Study Bible's internal cross-references.
- Tests updated: `bible-notes.test.ts` (new signatures; catalogue-line cases
  added: "Acts 2 (Pentecost and Peter's sermon)", "Mark 10:6 and the
  genealogies of Genesis 5 and 11", "Jude 14-15 with Jude 9", "Wisdom
  2:12-20"); `needs.test.ts` (the moved `studyBibleHref` block removed).

One in, one out: this adds no reader-facing surface; it removes three parsers

## Review (2026-10-26, adversarial reviewer, same worktree)

Verdict: ready with notes. The parser does what the card asks (the six card
references read identically in both runtimes with exact spans; unknown books
are null), the retirements are clean, and nothing reader-facing changed. Two
real bugs and one integration seam were fixed in commit 7e652294; the card's
`validate-essays.mjs` parse check still cannot land in this worktree (the file
is U03's) and is handed to the integrator below as a tested diff.

### Findings

1. **refChapters read "and 2 Timothy 4:20" as chapter 2 of the first book**
   (fixed). The docstring says an "and" that leaves the book stops the walk,
   but a numbered book after "and" starts with a digit, so
   `leadingRef("2 Corinthians 2 Timothy 4:20")` read "2 Corinthians 2". Five
   catalogue lines did this ("2 Corinthians 12:7-9 and 2 Timothy 4:20",
   "Matthew 24:24 and 2 Thessalonians 2:9", "Psalm 90:4 and 2 Peter 3:8",
   "Acts 16:14-15, 16:31-34, and 1 Corinthians 1:16", and "1 Timothy 2:3-4
   and 2 Peter 3:9", the last harmlessly), so the Miracles, Origins, and
   Sacraments doctrine pages were listed as related on 2 Corinthians 2,
   Matthew 2, Psalm 2, and Acts 1. The old parser had the same bug; the
   builder's old-vs-new comparison could not see it because both agreed.
2. **A catalogue line's opening reference was cut only at whitespace, ",",
   ";", or "("** (fixed). "Genesis 1:5. The day..." or "Genesis 1:5 (an em-dash) the
   day" read as null, where the old regex read Genesis 1. None in today's
   data; the catalogue is generated, so the next line like that would have
   dropped silently. It now cuts wherever a word or number ends.
3. **Verse-part letters were not read** (fixed; seam with U03). "Romans
   3:23b" was null in both parsers. The builder's note that none occur in the
   site's data is true of the fields these functions read, but half-verse
   citations sit in study-guide and Bible-note prose (John 18:36a, Matthew
   5:13a-c, Luke 22:19b, 1 Kings 19:4a), which U16's remark plugin will scan,
   and U03's `SCRIPTURE_REF_SOURCE` accepts "3:23b" by shape, so the card's
   parse check would have failed any essay citing a half-verse with a
   misleading "cannot read" message. Both parsers now read `[a-c]` after a
   verse number as the whole verse ("Luke 22:19b-20" is 22:19-20); "16ab",
   "16A", "Psalm 23a", and "16 b" stay null. Fixtures and an exact-span test
   added; the agreement test holds both.
4. **`validate-essays.mjs` parse check (card file) not wired** (open, for the
   integrator). The builder was right that it cannot land here. The diff
   below applies cleanly to U03's head (`git apply --check` in
   wf_4b2d5b16-bc3-1) and was tested on a temporary U03 + U09 tree in this
   worktree, then removed: `server/essay-gate.test.ts` 17/17 pass (with the
   new case), `node scripts/validate-essays.mjs` exits 0 (0 essay files
   today). Whichever lands second (U03 or U09) applies it. The 84 references
   in the five pilots, found with U03's regex, all read with `readRef`.
5. Performance (note, not changed): `itemsForPassage` over the 946-item
   catalogue went from about 4 ms to 8 ms per call in Node (it now tries a
   parse at each word end of a catalogue line). It runs on a verse tap and a
   chapter view; acceptable. A memo on `refChapters` is three lines if a
   phone trace ever shows it.
6. The SPLIT regex is quadratic on long letter-only strings (5,000 characters
   about 30 ms; 200 characters well under 1 ms). Harmless for references and
   catalogue lines; U15 should cap the Find field's input before parsing.
7. No conflicts with the other six wave-1 units: no file overlap with U03,
   U04, U06, U10, U12, or U14. U06 edits four `client/public/needs/*.json`
   files the agreement test reads, but only links, not passages. U12's
   `validate-family.mjs` uses `passage()`, whose verses are unchanged.
