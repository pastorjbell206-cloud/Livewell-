## What changed

**Data and build.**
- `scripts/lib/family-index.mjs` and `scripts/build-family-index.mjs` (new)
  write `client/public/family/index.json` (new, 56 KB, 12.6 KB gzip): one row
  per devotion page (the 72 weekly devotions by their frozen ids, and every
  day of the three daily sets as `thanksgiving-1..7`, `advent-1..25`,
  `holy-week-1..8`), each with title, theme or day label, passage, the Study

  this week's question without the 76 KB catechism file. The build stops on a
  set it has no address for, an address two devotions would share, or a
  passage the parser cannot read. `--check` is added to the CI content-gates

  family gate (which globs `family-*.json` and fails on an unknown kind) does

## Review (2026-10-27)

An adversarial pass over `git diff 23425fe7..HEAD` against the card (10.6),
5.2, 5.5 core, 5.6, 8.2, 9.3 and 9.9. The build holds: the route checklist is
complete, the index builds from the shared parser, the accordion, empty essay
rows and `posts.listPublished` call are gone, tokens only, literal SEOMeta on

problems were found and fixed in `ef4de72a`:

1. **"Next" landed at the bottom of the next devotion.** Before this and Next
   keep `DevotionPage` mounted and change only the id, and the site has no
   scroll reset, so the reader arrived at the end of the next devotion
   (Chromium: scrollY 2625 before and after). The page now jumps to the top
   when its id changes (instant, not the site's smooth scroll). Test added;
   Chromium now reads 0.
2. **The completion event counted taps, not nights.** Each tap of "We did this
   tonight" on a devotion page sent `family_devotion_complete` again.
   `recordDevotionDone` now reports `already`, and the event goes once per
   devotion per night on this device. Tests added (library and page).
3. **The wake lock was asked once, away from any tap.** Table mode mounts after
   the chunk and two fetches, so the first request is made with no user
   activation; a browser that wants one refuses and the screen sleeps for the
   rest of the meal. `useWakeLock` now asks again on the next tap or key (Next
   is a tap), never holds two, and forgets a lock the browser released. New
   `useWakeLock.test.ts` (4): one lock, ask again after a refusal, ask again on
   return to view, nothing when inactive or unsupported.
4. **Sibling seam with U13.** U13's Advent links (Home line, /family card)
   point at `/family/devotions?tab=advent&day=N`. The library now opens that
   day's own page (`/family/devotions/advent-N`, replacing history) when the
   set has that day, and stays on the tab when it does not. Tests added.
5. **Small a11y and first-paint items.** The tonight card was
   `aria-labelledby` a heading that does not exist while loading; it is now
   labelled by its eyebrow ("Tonight at the table"), always present. The
   season list on `/family` came only after the index arrived, so "The season"
   sat empty; it now reads the static year map at once (labels fall back to
   the set names until the index answers).
