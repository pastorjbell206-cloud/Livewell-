# U03 Essay gate (without the ESV cache)

Card (MASTER-PLAN 10.6, 9.2): `scripts/validate-essays.mjs` (references
present but not yet parsed); extend `validate-grow-voice.mjs` and
`validate-no-emdash.mjs` to `client/public/essays/` only; add the gate to
`ci.yml`. No ESV cache. Done when the gates pass on the current essays folder
and fail on a seeded bad file in a test.

## What changed

- `scripts/validate-essays.mjs` (new, CI gate). For each
  `client/public/essays/*.json`, or the files and folders named on the command
  line:
  - shape: the same `overrideProblems` rule `build-essays-index.mjs` uses (slug
    matches file, slug on the shelf, title, excerpt, body of 600+ characters,
    ISO `updated`), plus no unknown field, no H1 in the body (the page sets the
    title as the only H1), and no opening paragraph that repeats the excerpt;
  - Forbidden Language (CLAUDE.md list) in our own prose;
  - rulebook leakage from the BRIEF: steelman, verdict, indictment,
    self-implication, both-sidesism, the BRIEF's four example phrases, and
    "Not X. Y.";
  - dashes: no em-dash in our own prose, nor "word---word" (the essay renderer
    turns it into an em-dash), "--", or a spaced en-dash; title and excerpt
    carry none at all, even in a quotation, because they feed listings and
    `llms-full.txt`, which the em-dash ratchet scans raw; unspaced en-dash
    ranges (1914–1918, Luke 19:41–42) are fine;
  - exclamation points: none in our prose; inside a quotation only when a
    Scripture reference sits beside it (parenthetical after the closing mark,
    "Psalm 33:12:" right before the opening one, or at the end of a block
    quote); Markdown image `![` is not counted;
  - links: internal links must start with `/` and reach a public page
    directly: a `/writing/<slug>` whose shelf visibility is public (the files
    being checked count as public, since they go live together), or a route
    `scripts/lib/site-routes.mjs` resolves as "ok". A redirect source, a
    missing page, or an unverifiable param route fails. External links are not
    checked;
  - references present: the body cites Scripture by reference at least once,
    and a standalone italic quotation line (Closing Texts) reads
    `*"Quote."* (Reference)` with a Scripture reference on the same line;
  - an unpaired quotation mark in a paragraph fails, since the gate then
    cannot tell quotation from prose.
- `scripts/lib/essay-text.mjs` (new): quotation masking (double quotes,
  straight or curly, within a paragraph; `>` block quotes), link-target
  masking, Scripture reference by shape (book names from
  `client/public/bible/books.json` plus "Psalm" and "Song of Songs"; not a
  parse), `hasReferenceBeside`, `dashesIn`. Quotations keep their own words and
  punctuation, per NOTES ("Verbatim quotations keep their own punctuation").
- `scripts/lib/forbidden-language.mjs` (new): Grow voice's Forbidden Language
  list and allowed senses, moved unchanged so both gates read one list.
- `scripts/validate-grow-voice.mjs`: imports that list; adds the essays folder,
  where every quotation and link target is set aside (the BSB-only exemption
  cannot recognize ESV text); reads the Bible only when a BSB-checked file needs
  it; `--essays <dir>` checks only that folder (used by the test). Output on
  the existing 381 files is unchanged (clean).
- `scripts/validate-no-emdash.mjs`: adds the essays folder: no em-dash in title
  or excerpt, none outside quotations in the body ("---" counts);
  `--essays <dir>` for the test. Other scopes unchanged.
- `.github/workflows/ci.yml`: `node scripts/validate-essays.mjs` in the
  content-gates step, right after `validate-no-emdash.mjs` (moved there in
  review so U10's line after `validate-family.mjs` applies without a merge).
- `CLAUDE.md`: the CI gates line says 23 validators and lists "essays" after
  "no-emdash", matching ci.yml (one hunk; no other wave-1 unit edits CLAUDE.md).
- `client/public/essays/README.md`: one paragraph on running the gate and what
  it holds (no em-dashes in it).
- `server/essay-gate.test.ts` (new, 16 tests after review): helper unit tests; the three
  gates pass on the committed folder and on a seeded clean essay (ESV quote
  with an em-dash, Scripture exclamations with references before and after, a
  block quote, links to a live essay, /study/bible, /help, a Closing Text);
  they fail a seeded bad essay, and the test asserts each fault by name
  (unknown field, excerpt em-dash, H1, "navigate", "verdict", em-dash, "---",
  "--", "!" in prose, "!" in an unreferenced quotation, unpaired mark, a
  non-public essay link, a redirect link, a relative link, a Closing Text with
  its reference on the next line); an essay with no reference fails; a prose
  line after an italic quotation is not mistaken for a Closing Text.

## Review (second agent, 2026-10-26)

Read the card, 9.2, NOTES and the BRIEF against the diff; ran every gate
myself; probed the gate with about twenty edge cases; and ran all 23 CI
content gates with three mechanically fixed pilots placed in
`client/public/essays/` (then removed). The build did what the card asks, the
three gates agree with each other, and nothing else in CI (llms-full, the
catalogue, the links gate, content integrity) trips on a real essay with ESV
em-dashes inside quotations. Real problems found and fixed in commit e4e2f31:

- **Block-quote attribution escaped the em-dash rule.** A whole `>` paragraph
  was masked, so `> — Amos 3:2` under a block quote passed although the dash is
  ours, not the quotation's (the 15 pilot attribution dashes would have slipped
  through the moment a writer used a block quote). The attribution line (or a
  closing "— Reference" on the last line) now stays prose and fails; a dash
  attribution also counts as the reference beside the quote, so the "!" message
  is not doubled.
- **Block quote interrupting a paragraph** ("Paul wrote:" then a `>` line, no
  blank line) was read as prose, flagging the quotation's own dashes.
  react-markdown starts a block quote there, and so does the gate now.
- **"steel manufacturing" failed as rulebook leakage** (`steel[- ]?m[ae]n\w*`).
  Now only steelman and its forms; "self implication" without the hyphen is
  now caught.
- **A full-address link to this site was not checked** (treated as external),
  so `https://www.livewellbyjamesbell.co/writing/<retired>` would land readers
  on a notice. It now fails and names the path to use.
- **An H1 underlined with "="** passed; it now fails like `# Title`.
- Messages: an unpaired quotation mark suggests a block quote for a quotation
  longer than a paragraph; an off-shelf essay link says "retired, or a newer
  post the gate cannot see" instead of asserting it is retired.
- `essay-text.mjs` finds the repo root with `fileURLToPath` (the URL pathname
  form breaks on encoded paths, and U09 found Vite rewrites it); CRLF paragraph
  breaks split correctly.
- `ci.yml` line moved beside `validate-no-emdash.mjs` (see above).
- README: links by path, and block-quote attributions in parentheses.
